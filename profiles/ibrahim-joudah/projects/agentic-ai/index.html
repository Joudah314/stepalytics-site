Agentic AI job-market monitoring system: how it works

An LLM system that watches the Australian job market around the clock, filters thousands of ads with machine learning and LLMs, and hands a short list to a person who decides.

Running since October 2026 · Last reviewed 23 October 2026

Designed, built and run by me. The implementation is private; a walkthrough is available on request.

At a glance

  • About two-thirdsof strong-LLM calls avoided in a pilot on 691 ads, with no good or strong job missed compared with the full evaluation
  • 1,300+automated tests run on every change
  • Every applicationis decided and submitted by me; the system never presses Submit

The system today

How it was built, stage by stage

  1. 1

    Stage 1: Set the ground truth before automating

    Problem
    A system that writes about me must never claim anything untrue.
    Decision
    Before any code, I built a bank of about 150 statements about my work, each approved by me, and a list of claims never to make. The system enforces both in code, not only in the prompt.
    Rejected
    Letting an LLM write freely and checking afterwards.
  2. 2

    Stage 2: Design first, then build

    Problem
    A system with many parts can drift into inconsistency.
    Decision
    A written design with fixed contracts between parts (one database, one message queue, each part with one owner), automated tests and secret scanning on every change, and review before shared code changes.
    Evidence
    An independent review before launch found 2 blocking and 12 minor issues; all were fixed before going live.
  3. 3

    Stage 3: Screen cheaply, evaluate carefully

    Problem
    Most ads are poor fits, and reading every one with a strong LLM is slow and costly.
    Decision
    A cascade. Duplicates are removed and fixed rules applied in code, a fast LLM screens, and a stronger LLM evaluates the rest against my profile, returning structured output that is validated in code.
    Rejected
    One strong model on everything.
  4. 4

    Stage 4: Go live with a human deciding

    Problem
    Automated applications are a real concern for employers.
    Decision
    The system recommends and prepares; I review and submit every application myself.
    Evidence
    A review of the first 30 prepared applications found no claim outside the approved facts.
  5. 5

    Stage 5: Check the AI against people

    Problem
    An LLM’s ratings can’t be trusted just because they sound reasonable.
    Decision
    I grade ads blind, and a weekly sample compares my grades with the AI’s. Any change to the evaluator restarts the comparison.
  6. 6

    Stage 6: Cut paid calls without missing good jobs

    Problem
    The AI budget is fixed.
    Decision
    Machine-learning filters (XGBoost, and a model built on the fast LLM’s probabilities) decide which ads need the strong LLM. They ran in shadow mode first and switch on only if pre-set limits on missed jobs hold.
    Evidence
    In a pilot on 691 ads, about two-thirds of strong-LLM calls were avoided with no good or strong job missed. The first filter on its own saved little; most of the gain came from the second.
  7. 7

    Stage 7: Check at the right time, at scale

    Problem
    Jobs appear at different times across thousands of employers’ own sites, and checking everything constantly wastes load and budget.
    Decision
    A Bayesian model of when each source posts decides when to check it, and coverage includes the job pages of thousands of employers, checked under a load limit. Data-quality checks catch bad data: decoy links on some sites, which produced thousands of false jobs, were detected and excluded.
